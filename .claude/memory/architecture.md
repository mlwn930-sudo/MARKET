# החלטות ארכיטקטוניות — Market Intel

## Stack

| טכנולוגיה | למה בחרנו |
|---|---|
| Next.js 15 App Router | ריצה טבעית על Vercel; Server Components מאפשרים למשוך נתונים בשרת בלי לחשוף מפתחות |
| TypeScript | נתונים פיננסיים עם טיפוסים לא ברורים הם מקור באגים; טיפוסים מונעים חצי מהם |
| Tailwind v4 | RTL מובנה, עקביות עיצובית בלי CSS שגדל בלי שליטה |
| Recharts | מספיק לגרפים שלנו, קל משמעותית מאלטרנטיבות |
| Neon Postgres | חינם, מתחבר ל-Vercel בלחיצה, 0.5GB מספיק בהרבה |
| Drizzle ORM | קל ומהיר ב-serverless, בניגוד ל-ORM כבדים |

## ההחלטה המרכזית: שכבת מקורות אחת

כל קריאה לשירות חיצוני עוברת דרך `src/lib/sources/`. אין `fetch` ישיר
משום מקום אחר בקוד.

**למה:** SEC חוסמת מעל 10 בקשות לשנייה. אם קריאות מפוזרות בקוד אין
נקודה אחת לאכוף בה מגבלה, ומספיק עמוד אחד עם לולאה כדי לחסום את
כל הפרויקט. נקודת מעבר אחת = rate limiting, cache ו-retry במקום אחד.

## ההחלטה השנייה: מפרידים בין איסוף לחישוב

- `src/lib/sources/` — **מביא** נתונים גולמיים. לא מחשב כלום.
- `src/lib/metrics/` — **מחשב** מדדים מנתונים גולמיים. לא מביא כלום.
- `src/lib/agents/` — **מרכיב** תמונה מהשניים.

**למה:** נוסחת P/E לא צריכה להשתנות כשמחליפים ספק מחירים. ההפרדה
הזו היא מה שיאפשר לשדרג ל-API בתשלום בעתיד בלי לגעת בחישובים.

## ההחלטה השלישית: המודל קורא, לא יודע

כל פיצ׳ר מבוסס-מודל באתר — הצ׳אט, מחקר העומק, התדריך וניתוח כתבה —
בנוי באותו סדר: **קוד אוסף נתונים → המודל קורא אותם → המודל כותב.**
המודל לא מחזיק כלים, לא מושך כלום, ולא מוסיף מספר משלו.

**למה:** מודל שפה שנשאל על אנבידיה ייתן מכפיל מהזיכרון, מהתאריך שבו
האימון שלו נגמר, בפורמט זהה למכפיל שחושב הבוקר מהדוח. הקורא לא יכול
להבדיל ביניהם. לכן:

- `sources/gemini.ts` — הקריאה היחידה למודל, עם מגבלת קצב ותקציב.
- `analysis/prompts.ts` — החוקים (אסור לדרג, אסור להמליץ, אסור מספר
  שאינו בבלוק). מקום אחד, כי עותק שני היה נסחף בלי שאיש ישים לב.
- `analysis/context.ts` — בלוק הנתונים. כל מספר נושא מקור ותאריך.

**המחיר:** תשובה על חברה שלא נאספה תגיד "אין עליה נתונים" במקום
לנחש. זה נכון, וזה גם מה שהופך את שאר התשובות לשוות משהו.

## דברים שהחלטנו לא לעשות

- **אין חיבור לברוקר ואין ביצוע עסקאות.** לא עכשיו ולא בעתיד.
- **אין ייעוץ השקעות מותאם אישית.** המערכת מציגה נתונים וניתוחים;
  ההחלטה היא של המשתמש. דיסקליימר בכל עמוד ניתוח.
- **אין נתוני אופציות ואין מסחר תוך-יומי.** מחוץ לתחום — הפרויקט
  מכוון לטווח בינוני-ארוך, והנתונים האלה עולים כסף.
- **אין מערכת משתמשים מלאה.** סיסמה אחת פשוטה מספיקה למעגל הקרוב.
- **אין Yahoo Finance.** אין API רשמי, וה-endpoints נחסמים לסירוגין.

   לכל מדד, אחרת יהיו חורים בנתונים.
