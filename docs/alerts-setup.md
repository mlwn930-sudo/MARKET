# הפעלת ההתראות

שני שירותים, שניהם בחינם, ואחד מהם מספיק כדי להתחיל.

הקוד כבר כתוב ועובד. מה שחסר זה שני מפתחות. **כל עוד הם חסרים האתר
עובד רגיל** — הדלת נפתחת, הכתובת נבדקת, פשוט אין איפה לשמור ואין
דרך לשלוח.

---

## שלב 1 — איפה הכתובות נשמרות (Neon)

1. להיכנס ל-<https://neon.tech> ולהירשם (אפשר עם GitHub).
2. ליצור פרויקט חדש. השם לא משנה.
3. במסך שנפתח יש **Connection string**. הוא נראה כך:

   ```
   postgresql://neondb_owner:XXXX@ep-xxxx-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```

4. להעתיק אותו, ולהדביק בקובץ `.env.local` בשורה:

   ```
   DATABASE_URL=postgresql://...
   ```

**אין מה להריץ אחרי זה.** הטבלה נוצרת לבד בפעם הראשונה שמישהו נרשם.
אין מיגרציה, אין `db:push`.

## שלב 2 — איך המייל נשלח (Resend)

1. להיכנס ל-<https://resend.com> ולהירשם **עם הכתובת שאליה אתה רוצה
   לקבל את ההתראות** — זה חשוב, ראה את ההסתייגות למטה.
2. ללכת ל-<https://resend.com/api-keys> וללחוץ **Create API Key**.
   הרשאת **Sending access** מספיקה.
3. להעתיק את המפתח (הוא מוצג **פעם אחת בלבד**) ולהדביק ב-`.env.local`:

   ```
   RESEND_API_KEY=re_xxxxxxxxxx
   ```

### ההסתייגות שחשוב לדעת מראש

בלי דומיין מאומת, Resend שולח **רק לכתובת שפתחה את החשבון**.

מה זה אומר בפועל:

| | עובד עכשיו? |
|---|---|
| מייל אישור כשמישהו נרשם → אליך | ✅ |
| התראות על הזדמנויות וכתבות → אליך | ✅ |
| התראות לאנשים אחרים | ❌ עד שיהיה דומיין |

**זה בדיוק מה שביקשת** — אתה רוצה לקבל הודעות. זה עובד ביום הראשון.

אם בעתיד תרצה שגם אחרים יקבלו: לאמת דומיין ב-<https://resend.com/domains>
ואז למלא `ALERT_FROM` בכתובת עליו, למשל `MARKET <alerts@yourdomain.com>`.

## שלב 3 — לבדוק שזה עובד

```bash
npm run watch
```

זה סורק את כל 123 החברות וכותב את מה שמצא. אחר כך:

```bash
npm run alerts
```

מה שתראה:

| פלט | מה זה אומר |
|---|---|
| `no DATABASE_URL` | שלב 1 לא הושלם |
| `no RESEND_API_KEY` | שלב 2 לא הושלם |
| `no approved subscribers` | הכל מחובר — פשוט עוד לא אישרת אף כתובת |
| `N findings sent to 1/1 subscribers` | נשלח |

כדי להגיע ל"נשלח" צריך להירשם פעם אחת:

1. להריץ `npm run dev`, לפתוח את האתר, להקליד את הכתובת שלך בדלת.
2. מגיע אליך מייל **"בקשה חדשה להתראות"** עם שני כפתורים.
3. ללחוץ **לאשר** — מהטלפון, מהמייל.
4. להריץ שוב `npm run alerts`.

## שלב 4 — שזה ירוץ בלעדיך

הסריקה והשליחה כבר מחוברות למשימה המתוזמנת שרצה ממילא
(`.github/workflows/refresh-news.yml`) — כל חצי שעה בשעות המסחר,
פעמיים ביום מחוצה להן.

כדי שהיא תוכל לשלוח, אותם מפתחות צריכים להיות גם ב-GitHub:

**Settings → Secrets and variables → Actions → New repository secret**

| שם | ערך |
|---|---|
| `DATABASE_URL` | אותו connection string |
| `RESEND_API_KEY` | אותו מפתח |
| `ALERT_OWNER_EMAIL` | `mlwn930@gmail.com` *(לא חובה — זו ברירת המחדל)* |
| `NEXT_PUBLIC_SITE_URL` | כתובת האתר, אם יש |
| `ALERT_FROM` | רק אחרי אימות דומיין |

בלי הסודות האלה המשימה עדיין רצה ועדיין סורקת — היא פשוט לא שולחת,
ולא נכשלת בגלל זה.

## מה ייכנס להתראות

ארבעה סוגים, והם מסודרים לפי כמה הממצא חורג מהרגיל:

- **הזדמנות** — חברה שעוברת את רוב מבחני הסורק **וגם** ירדה חריג או
  יושבת בשפל רבעוני. שני החצאים יחד, כי אף אחד מהם לא מעניין לבד.
- **תנועה חריגה** — יחסית לתנודתיות של אותה חברה, לא סף אחיד.
- **מועד מתקרב** — תאריך שחברה אישרה, בתוך שלושה שבועות.
- **כתבה מהותית** — כזו שהניתוח סימן כבעלת משמעות גבוהה.

**קצה טווח לבדו לא נשלח.** הוא מעניין בעמוד ולא שווה להפריע בשבילו.

**יום שקט לא שולח כלום.** הודעה יומית שאומרת "לא קרה כלום" היא הדרך
המהירה ביותר לגרום לך להתעלם מהבאה.

**ולא תקבל את אותו ממצא פעמיים.** הסורק רץ כל חצי שעה, וחברה שחרגה
בבוקר עדיין חורגת בריצה הבאה — לכן לכל ממצא יש טביעת אצבע של
סוג + חברה + יום, ומה שנשלח לא נשלח שוב.
